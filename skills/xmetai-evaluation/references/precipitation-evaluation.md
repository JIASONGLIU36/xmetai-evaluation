# 降水分类检验：口径与产出

本文件说明**降水分类检验（TS 系列）**的数据口径与产出契约，与
`xmetai_evaluation/visualization/` 的实现、以及 `SKILL.md` 的工作流一致。
**冲突时以代码为准**——本文件是代码的散文镜像，改口径先改代码，再回来改这里。

---

## 1. 评估在做什么

把**预报**与**观测**按有效时刻配对，在若干个降水阈值上做二值化，得到 2×2 列联表，
再算 TS / POD / FAR / 漏报率 / BIAS。指标定义见 `evaluation-metrics.md`。

一个"结果表"就是这些指标在 **（累积窗口 × 预报时效 × 降水等级）** 三个维度上的排列。

---

## 2. 输入契约

必需列：`lead_h`、`grade`、`TS`

常见可选列：`window_h`、`threshold_mm`、`hits`、`misses`、`false_alarms`、
`n_pairs`、`POD`、`FAR`、`漏报率`（或 `miss_rate`）、`BIAS`

```csv
window_h,lead_h,grade,threshold_mm,hits,misses,false_alarms,n_pairs,TS,POD,FAR,漏报率,BIAS
24,24,≥0.1,0.1,1059516,58708,886518,3648837,0.528505,0.947499,0.455551,0.0525011,1.74029
```

- 多出来的列（如 `run_id`）忽略；
- `漏报率` 缺失时由 `1 − POD` 推导；`threshold_mm` 缺失时从 `grade` 解析；
- **必需列缺失就停下来说明**，不要猜。

> 阈值表随窗口而变：24h 常用 `0.1/10/25/50/100`，6h 常用 `0.1/13/25`。
> **不同窗口的阈值不可混在一张图上比较。**

### 2.1 概率评分表（`diagnostics/probability_wide.csv`，只有集合跑法有）

跟 TS 那份**分开放**：TS 在 `diagnostics/categorical_wide.csv`，概率评分在
`diagnostics/probability_wide.csv`，两份都由 v2 能力直接写出。

```csv
window_h,lead_h,grade,threshold_mm,AROC,BS,BS_ref,BSS,base_rate,n_points,n_used
6,24,≥0.1,0.1,0.905477,0.12948,,0.0607429,0.165117,3.66013e+06,
6,24,AVG,,0.832283,0.0439618,,0.142172,,,4
```

- **有产物带 AVG 行、也有产物不带**：渲染器两者都吃——没有 AVG 行时自己按
  **可算阈值等权平均**算出来（某档无有效值就跳过，不拿 0 顶替）；
- `BS_ref` 只有**给了外部气候概率参考的 6h 窗**才有值，其余窗口整列为空；
- **这张表不进** `diagnostics/categorical_wide.csv`，是独立的一份；
- 报告侧**只认表在不在，不认文件名**：在主模型目录、以及每个 `--compare` 的
  **同目录**各找一次，先找 `probability_wide.csv`，再找老命名的 `aroc_bss*.csv`
  （`weather_ts_ens_aifs` 那种只把两张裸 CSV 并排放在一起的归档），找到的进第六节，
  两份都没有的那份只出 TS（老 `ts_multi_*` 归档就是这种）；
- 指标定义见 `evaluation-metrics.md` §2，判读门槛见 `diagnostic-rules.md` §6。

## 3. 统计口径（最容易出错的地方）

**比率必须用合计口径**：先沿时效把列联表合计（Σhits / Σmisses / Σfalse_alarms），
再由合计值算比率；报告里同行的计数也必须是同一批样本的合计。

**禁止**把"多时效合计的 hits"和"单时效的 n_pairs"放在同一行——这会让
`hits > n_pairs`，看上去像编数据。

报告同时给出两种口径并注明：

| 口径 | 含义 | 用途 |
|---|---|---|
| 合计（主） | 先合并列联表再算比率 | 与计数自洽，可核对 |
| 等权平均（参考） | 各时效先算比率再平均 | 与"逐时效曲线"一致 |

### 3.1 概率评分的口径与 TS 完全不同

| | TS 系列 | 概率评分（AROC / BS / BSS） |
|---|---|---|
| 插值到站的时机 | 先算**集合平均场**，再插值 | **逐成员**插值 |
| 判事件 | 集合平均场 ≥ 阈值 | **超越式**（`x ≥ 阈值`）逐成员判，再求成员比例 |
| 窗口 | 24h（配 24h 的阈值表） | 6h（**独立**的阈值表） |
| 汇总 | 先合计列联表，再算比率 | 逐样本算 Brier，再求平均 |

**两套口径的数不可互换、不可同图对比。** 报告里同时出现时要分别标注口径。

### 3.2 集合平均场 ≠ 集合的全部信息

`weather_ts_ens` 的 TS / POD / FAR / 漏报率 / BIAS **都是在集合平均场上算的**，
是**确定性口径**——一个成员高度一致和成员四散分布的两个集合，这五个数可以完全相同。
成员信息只在概率评分那一节体现（见 `evaluation-metrics.md` §3.3 的 Spread/RMSE）。
报告里不要用"集合的 TS 高"去论证"集合有优势"。

## 4. 样本量门槛

| 条件 | 判定 |
|---|---|
| `events = hits + misses = 0` | 不可评定（样本库物理上限，不是模型缺陷） |
| `0 < events < 50` | 仅参照（方差大），曲线上用虚线并标注 |

细节见 `diagnostic-rules.md`。

> 概率评分用的是**另一套计数**：`n_points`（样本点数）与 `n_used`（参与 AVG 的档数），
> 和 `events = hits + misses` **不是一回事**，两边的门槛不能互相套。

## 5. 产出契约

```
reports/<模型>_<批次>/
  ${window}h_TS_vs_lead.png           时效-技巧曲线（按等级分线；样本少的等级虚线）
  ${window}h_POD_vs_lead.png
  ${window}h_FAR_vs_lead.png          Y 轴锁 0–1
  ${window}h_BIAS_vs_lead.png         Y 轴自适应 + BIAS=1 参考线（**不截断**）
  ${window}h_metrics_by_threshold_<lead>h.png
  ${window}h_TS_heatmap.png           等级 × 时效（数字颜色随底色自动切换）
  ${window}h_performance_diagram_<lead>h.png
  ${window}h_TS_boxplot.png           各模型 TS 跨时效分布（箱线图）
  ${window}h_multi_model_TS_delta_vs_<主模型>.png   多模型**差值**对比
  REPORT.md
```

集合那份还多一张概率评分的图（`${概率窗口}h_AROC_BSS_vs_lead.png`，骨架里是图 9），
**窗口前缀取概率表自己的 `window_h`（6h），不是 TS 的 24h**——两套口径不共用一个前缀。
它跟第六节的表、小结一起，只在拿得到概率表（`probability_wide.csv` 或老命名的
`aroc_bss*.csv`）时出现；没有那张表时这一节连同它的图表号一起消失，后面的号自己收回来。

`REPORT.md` 写成**论文实验章节**的样子——每节是「引导句 → 图表 → 小结」，
不是"表格 + 末尾一堆裸图"。二 / 三 / 四 / 五这四节**三个分支逐字相同**：

```
一、结论摘要（先交代评估对象与口径：模型 + 来源文件 + 可比性声明 + 记录条数 + 指标；
             再**一整段**结论，不列点；末尾业务定性与指标定义）
  → 二、逐降水等级表现（全时效平均）          表 1 + 图 1
  → 三、TS 随时效变化（{首}–{末}h）            图 2、图 3 + 表 2
  → 四、误差形态与偏差结构                    图 4–图 7
  → 五、跨时效分布（箱线图，TS）               表 3 + 图 8
  → （三个分支从这里开始分叉）
```

分叉之后的章节链：

| 分支 | 什么时候用 | 章节链 | 骨架 |
|---|---|---|---|
| **A 单模型** | 没给对比对象 | 六、改进建议 → 七、口径与注意事项 | `weather_ts_single.md` / `weather_ts_ens.md` |
| **B 单基准** | `--compare` 给了一个 | 六、与基准对比（**只有表**）→ 七、改进建议 → 八、口径 | 同上 |
| **C 多模型** | `--compare` 给了两个及以上 | 六、与对比模型的比较（表 + **差值图**）→ 七、改进建议 → 八、口径 | 同上 |

> B 分支**没有图**：多模型差值图（`multi_model_TS_delta`）只在给了多个对比对象时生成。
> 单基准的表体是"本模型 / 对比模型 / 差值"三列，多模型是横表 + 本模型名次。

**集合那条（`weather_ts_ens`）在第五、六节之间多插一节**：
「六、概率评分（AROC / BSS）」——TS 系列评的是集合平均场，成员的离散信息
没有进入任何指标，这一节补上。于是它后面的对比节与建议/口径**整体后移一位**，
集合那份的分支 A 到「八」、B/C 到「九」，图与表也各多一个号。
**除此之外两份骨架逐字相同。**

几条硬约定：

- **没有"图表索引"节**。每张图都就地带着图注出现，再在末尾列一遍纯属重复。
- **图注在图下方、表题在表上方**（中文论文惯例）。写成 `图 N：…` / `表 N：…`，
  N 是**按在文档里出现的顺序**编的。
- **图与表的号随分支变**（跳过一张会让读者以为中间掉了一张，所以**缺图不留空档**）：

  | 分支 | 确定性（`weather_ts_single`） | 集合（`weather_ts_ens`） |
  |---|---|---|
  | A 单模型 | 图 1–8，表 1–3 | 图 1–9，表 1–4 |
  | B 单基准 | 图 1–8，表 1–4 | 图 1–9，表 1–5 |
  | C 多模型 | 图 1–9，表 1–4 | 图 1–10，表 1–5 |
- **每节末尾都有一段 `**小结**：`**，写的是定量 + 定性的分析（见 §6.9），
  不是"本模型表现良好"这类套话。文字由 `ts_report.py` 的 `analysis_*` 系列生成，
  它们**只吃已经算好的统计量，不重新读表、不重新实现指标**。

第五节的分位数表是**箱线图的数字版**，两者由同一个 `box_stats()` 算出来，
不可能不一致。读法：样本 = 同模型同量级在全部时效上的 TS；**TS 越高越优**，
所以箱子**越高**表示该量级整体技巧越好、**越窄**表示跨时效越稳定。
注意它与第二节的「全时效平均」不是同一个量（等权平均 vs 中位数/IQR），
两者给出不同的领先者是正常现象，**不可互相替代**。

## 6. 制图约定（踩过的坑）

1. **Y 轴不是越"动态"越好**：`TS/POD/FAR/漏报率` 是 [0,1] 的比率，
   **必须锁 0–1**；纯动态刻度会让个别点"穿顶"，视觉上像数据出错。
   只有 `BIAS` 用自适应刻度（它无上界），并画 `=1` 参考线。
2. **样本少的曲线要标出来**（虚线 + "样本少，仅参考"），否则会误导读者。
3. **热力图数字要随底色切黑/白**，浅底黄字看不清。
4. **多模型对比画差值**：模型水平接近时（如 0.529/0.519/0.507/0.504）
   绝对曲线会重合成一团，差值曲线才能回答"谁在哪档领先"。
5. **中文字体必须自动探测**（Linux 上没有 SimHei），且字体设置要在
   `plt.style.use` **之后**，否则会被样式覆盖成方块。
6. **箱线图按 Tukey 几何、与 matplotlib 同口径**：分位数用
   `np.percentile(values, [25,50,75])` **默认参数**（线性插值，不传 `method=`）；
   栅栏是 `Q1−1.5·IQR` / `Q3+1.5·IQR`；**须线画到栅栏内最远的那个点**，
   栅栏内一个点都没有时退到 `Q1`/`Q3`——不是"把极值夹到栅栏"。
   这条口径由 `tests/unit/visualization/test_ts_report.py::test_box_stats_matches_matplotlib`
   拿 `matplotlib.cbook.boxplot_stats` 当神谕逐项钉着（神谕就是画图那套代码，
   所以"表和图不一致"从根上不可能）。
   中位线必须显式压成黑色：rcParams 的 `boxplot.medianprops` 默认是**橙色**，
   不写就和"箱中横线为中位数"的直觉对不上。离群点画**空心**圆。
7. **一个箱体一次 `ax.boxplot` 调用**（`positions=[pos]`，`manage_ticks=False`）。
   好处是每个箱子能单独上色，且某模型缺某个量级时可以整块跳过——
   **不能把空数组喂给 matplotlib**（`ax.boxplot([[]])` 的行为随版本变，还会吐
   `RuntimeWarning`）；跳过的槽位在图上标一行小字"无有效值"。
   刻度在循环结束后统一 `set_xticks`，否则最后一次调用的定位器会覆盖前面的。
8. **图注与编号由 `_Numbering` 统一发，正文不自报号**。图和表各自按**出现顺序**
   编号（`图 1`…`图 N`、`表 1`…`表 M`），`_figure_block()` 出图时顺手取号。
   **产物里缺某张图时，连图注一起不出现、后面的号也不留空档**——
   编号跳跃（图 1、图 3）会让人以为中间掉了一张。
   正文与分析文字**不复述图号**（"如图 3 所示"这类），要指代就直接说
   "第二节的表 1"这种**按内容点名**的说法，免得图缺了以后正文挂着一个不存在的号。
   **差值图的纵轴方向是个坑**：`plot_multi_model_vs_lead(mode="delta")` 画的是
   `对比模型 − 参照模型`，图注必须写明"正值表示对比模型领先"，
   写反了整节的结论就颠倒了。
9. **每节小结不是装饰，是这一轮报告的正文**。`analysis_by_grade` /
   `analysis_by_lead` / `analysis_error_structure` / `analysis_stability` /
   `analysis_comparison` 各自产出**带具体数值**的一段话：说清分级分布、
   断崖出现在哪两档之间、各量级的有效时效上限、误差形态从哪一档由空报为主
   翻转为漏报为主、离群时效集中在短时效还是长时效、领先者是否随量级交叉。
   **算不出结论就如实写"数据不足以判断"**，不许用套话填空——
   `test_every_analysis_section_has_a_summary_with_numbers` 会检查每段小结里
   至少有一个数字。
   两个容易自相矛盾的点要盯住：并列时**不能报领先者**（差距 < 0.005 一律视为并列，
   与 `_baseline_table` 里 ↑/↓/≈ 用同一个门槛），名次用**并列同名次**的竞赛排名
   （名次 = 比自己高的对象个数 + 1），否则表里写 `3/3`、正文算出第 2，读者只会信一个。

## 7. 常见情形

| 情形 | 处理 |
|---|---|
| 数据里没有 24h | 用数据中最小的时效，并在报告里写明用的是哪个 |
| 只有 6h 窗口 | 阈值口径是 `0.1/13/25`，与 24h 不同，不要混比 |
| 只有单模型 | 出单模型报告，跳过对比章节（箱线图照出，一个量级一个箱体） |
| 只有长表 `scores.csv`、没有宽表 | **不合成**——`SKILL.md` 里也没有"长表→宽表"这个转换器，两份口径混用比报错危险。在评测配置里加上 `writers=["csv_long", "categorical_wide"]` 重跑 |
| 要对比多个模型 | `--compare "名字=宽表路径"`（可重复）；对比对象是**宽表**，不是产物目录（没有 manifest，认不出能力） |
| 要对比多个模型、但没说对比谁 | 看主模型目录的**同级目录**：有 `diagnostics/categorical_wide.csv` 的就是候选（`_archive/` 不算）；名字取 `run_id` 去掉 `weather_ts_det_` / `weather_ts_ens_` 前缀的模型简称；**先把清单报给用户确认**再跑 |
| 两个目录看着是同一个模型 | 逐格比 `n_pairs`——完全一样就是同一次评测的两次运行，别同时放进对比图（会画出两个重合的箱子） |
| 集合预报 | **两份产物**：`diagnostics/categorical_wide.csv` 里是**集合平均场**的 TS（确定性口径），`diagnostics/probability_wide.csv` 里才是概率评分。报告走 `weather_ts_ens.md`，多一节概率评分；两套数**不要混图**（见 §3.1） |
| 集合跑法没给 `--ref` | `BS_ref` 整列为空，BSS 算不出来——如实写"无气候基准"，别拿别的窗口顶上 |

## 8. 待办：空间分布图（"卫星图"）

**现状：产物里没有任何能画成地图的数据，这一轮画不出降水空间分布图。**
不是没写绘图代码的问题，是**数据在更上游就被扔掉了**。查证如下：

| 环节 | 事实 |
|---|---|
| 配对 | `EvaluationBatch.forecast` / `.observation` 是**带 lat/lon 的 `xr.Dataset`**，逐点场在这一步还在 |
| 指标 | `metrics/categorical.py:103-105` 用 `forecast[mask]` / `observation[mask]` **展平成一维**，115-118 行直接 `np.sum` 求列联表——**逐点信息到这里就没了** |
| 落盘 | 长表 `SCORE_COLUMNS` / `DETAIL_COLUMNS`（`results/table.py:26-68`）里**没有 lat/lon 列**；`region` 列只在配了 `options["regions"]` 分纬度带时才有值（带名，全球行为空——见 §9），`level` 列在降水检验里始终为空 |
| 绘图 | `visualization/` 全目录**没有任何 lat/lon 引用**，也没有 cartopy / 投影 / 海岸线依赖 |

所以要出空间图，得在**评测侧**补三件事，而不是只在可视化侧加个函数：

1. **指标端**：新增一个保留逐点场的 metric（或在 `accumulate` 之外单独累积
   命中/漏报/空报的逐点掩码），产出"每格/每站的 TS 或事件计数"这种二维场；
2. **落盘端**：新增一个 writer 把该场写成 netCDF（或 GeoJSON/TIF）落到 `diagnostics/`，
   ——长表是标量表，塞不下二维场，`output/table.py` 的模块注释里也写明了
   "空间场、ROC、功率谱等大对象不进长表"；
3. **重跑**：在评测配置里启用上述 writer，把已有结果重跑一遍。

在此之前，本 skill 的报告**只做统计图表，不做地图**；`SKILL.md` 里也不应承诺空间分布。
用户明确表示本轮先不做，等这两件事（新 metric + 新 writer）落地后再回来补这一节。

## 9. 分纬度带结果（`options["regions"]`）

在评测配置里配了 `options["regions"]` 时，站点协议（`station_valid_time`）除全球
样本外再逐带发一份样本——**站点按站点纬度整站归带**（读 `station_lat`，退而求
`lat`；两者都取不到**直接报错**，不静默回退成全球分）。带宽表里因此多出
`region` 列非空的行，报告写进末尾的**「附 L 分纬度带结果（可选）」**。

几条口径：

- **正文只算全球行，附 L 只算带行，两者永不合并**。各带平均再平均 ≠ 全球平均，
  混着算会把带间差异整个抹平。这条与 RMSE 家族的「附 L」是同一条规矩
  （见 `rmse-batch-evaluation.md`），渲染器侧共用 `precipitation_plots.split_regions`。
- **带名照搬配置，报告不翻译、不写死任何带名**。配置里叫 `南方` 就显示 `南方`，
  报告里显示的 `南方 [0, 25]` 是渲染时拼的界——**长表里只有裸名**，边界要去
  `manifest["regions"]`（顶层列表，形如 `["南方[0, 25]", …]`）或配置里取。
- **边界是闭区间**，正好压线的站两条带都算（与格点侧 `parse_regions` 同口径，
  改成一端开会让两类产物的分带对不上）。
- 表按**南界从低到高**排（按带名排中文是乱序）；判读句里的并列按**表里的显示
  精度**判定，并列就写并列，并写明头名是否随预报时效翻转。
- 图走**独立编号空间 `图 L1`**，不进正文 `图 1..N` 的连续性检查——加不加这一块，
  正文的图号一个都不动。没配分带的产物照样有这一节，写「**本块本批未出。**」。
- 这一块**只汇总主模型**：对比模型走对比节。按带切和按模型切是两个正交的维度，
  硬塞进同一张表会出现「同一个名字既是带名又是模型名」。
- 各带站点数差得远时 TS 的抽样噪声不一样，差一两个百分点不必当结论。

本仓库现用四带（`weather_ts_single_fgvp.py` / `weather_ts_ens_fuxi.py`）：南方
`[0, 25]` / 长江中下游 `[25, 32]` / 华北 `[32, 40]` / 东北 `[40, 90]`。换一套切法改
配置重跑即可。

集合那份（`weather_ts_ens_fuxi.py`）有两点不同：

- `options` 是**两段共用**的（见 `pipelines.py` 顶部），所以 24h 的 TS 段和 6h 的
  概率段**都会**出带行。带样本与全球样本共用 `build_batch` 缓存的那个批次，全场
  插值只做一次，代价是计算量 ×5 而不是读盘量 ×5。
- 报告的「附 L」只汇总 24h 那段的 TS。概率段的带行照常落进 `scores.csv` 与
  `diagnostics/probability_wide.csv`（两个宽表的 `region` 都在透视键里），只是
  报告不出——第六节（AROC / BSS）**目前没有渲染器**，见
  `assets/templates/weather_ts_ens.md` 顶部那条说明。
