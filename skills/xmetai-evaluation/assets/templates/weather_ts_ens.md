# 集合降水分类检验报告骨架

覆盖 `weather_ts_ens` 一条流程，渲染器与确定性那份共用
（`visualization/ts_report.py`），输入同样是产物目录里的
`diagnostics/categorical_wide.csv`。确定性两条流程（`weather_ts_det` /
`fdp_precip_ts`）是 [`weather_ts_single.md`](./weather_ts_single.md)——
**集合单独成篇**，因为除了成员口径，这一份还多一整节概率评分。

**照这个填空就是最终报告。** `{…}` 是占位符，**其余每一个字逐字照抄，不许改**——
包括标点、加粗、`>` 引用块、表头与分隔行、图注与表题的位置。

## 与 `weather_ts_single.md` 的差别

章节写法、编号规则、二～五节的内容**完全一致**，差别只有两处：

- **口径行多了集合口径**：头部多一行「集合成员数」，并声明 TS / POD / FAR / 漏报率 /
  BIAS **都在集合成员平均场（ensemble mean）上计算**——是确定性口径的评分，
  不是逐成员评分后再平均。成员之间的离散信息不进入这五个指标；
- **比确定性那份多一节「六、概率评分（AROC / BSS）」**：成员分布终于用上了，
  AROC 看区分能力、BSS 看相对气候基准的技巧。因为它插在第五节之后，
  后面「改进建议 / 口径与注意事项」以及对比节、雷达图节的**章节号整体后移一位**；
- **有对比对象时多一句样本量披露**：各份来源的实测配对数**并不相同**
  （起报日数不同，站点数每天大体固定），第一节里紧接对比对象说明写出各自的
  配对数与比值，末节「口径与注意事项」再加一条提示。只有一份来源时**不写**——
  没有第二份就没有「差多少」这回事。

**成员数由命令行给**（`--members N`，如 `--members 51`）：产物里**没有**这个字段，
`manifest.json` 不写、`scores.csv` 也不算（它的 `n_requested` 被阈值个数放大过，
不是样本量）。不给则报告里凡要写成员数的地方一律写成「集合成员」，**不编数字**。

概率评分那一节**时间窗与阈值都和 TS 不同**（TS 是 24h 累积窗、阈值
0.1/10/25/50/100/250mm；AROC/BSS 另有自己的窗与阈值，本仓库现用的 6h 窗是
0.1/4/13/25mm）。两套口径既不可比、也不要画进同一张图——这正是本节
**单独立节、单独编号**的理由。

报告按**论文实验章节**写：每一节都是「引导句 → 图表 → 小结」。
**图注在图下方、表题在表上方**（中文论文的排版惯例），图和表按在报告里出现的顺序
连续编号（`图 1`…`图 N`、`表 1`…`表 N`）。

三份骨架：单模型（默认）、有对比对象（单基准）、有对比对象（多模型）。
二 / 三 / 四 / 五 / **六**这五节**三个分支完全一样**，差别在对比节、雷达图节和
后面的章节号。

**模型能力雷达图只在有对比对象时出现**（单模型画一个多边形没有比较对象），
所以骨架 A 没有那一节；B 里它是第八节（图 10），C 里也是第八节（图 11——
B 没有那张多模型差值图，号比 C 少一个）。轴与口径同 `weather_ts_single.md`，
两边的这一节**逐字相同**，改一处就要改两处。

**编号契约**：骨架 A 是 `图 1..9` + `表 1..4`，骨架 B 是 `图 1..10` + `表 1..5`，
骨架 C 是 `图 1..11` + `表 1..5`；编号必须连续、不跳号不重号，每张图都必须在正文里
出现过。

**末尾的「附 L」是可选的**（有没有分纬度带结果都占这一节），它的图走**独立编号
空间 `图 L1`**，不进正文 `图 1..N` 的连续性检查——这样加不加这一块，正文的图号
一个都不动。带名与边界**照搬配置**，报告不翻译也不写死任何带名。写法与
`weather_ts_single.md` 那一块**逐字相同**，改一处就要改两处。

> **本骨架目前没有测试守着**（`tests/` 在这个仓库里是空的，见 `README.md`
> 的「怎么被保证」）。`weather_ts_single.md` 有 `tests/unit/visualization/test_ts_report.py`
> 逐字扫描，这一份**没有**；改 `ts_report.py` 的渲染时得自己回来对一遍骨架，
> 别指望 CI 红给你看。
> **占位符不要跨行写**——`{` 和 `}` 两边都算占位符标记。

> **第六节的数据来自 `diagnostics/probability_wide.csv`，有就出、没有就整节消失。**
> 它由独立能力 `weather_ts_ens_prob` 写出，配置里写
> `pipeline=["weather_ts_ens", "weather_ts_ens_prob"]` 才会有；只跑主能力、
> 或对比模型给的是裸宽表（旁边没有这张表）时，那几份就没有概率评分。
> **一节消不消失看的是表在不在，不是看模型是谁**——这正是本节章号由渲染器
> 现算（而不是写死「六」）的理由。
>
> 表里每个时效每个等级一行，另有 `grade="AVG"` 综合档；**没有 AVG 行时由渲染器
> 自己按可算阈值等权平均算出来**，不劳产物操心。列是
> `window_h, lead_h, grade, threshold_mm, AROC, BS, BS_ref, BSS, base_rate, n_points`。
>
> **多模型时表头多一列「模型」**：这份骨架的单模型分支（A）没有那一列；
> 报告里**有两个以上模型带概率表**时才加，只主模型有表就不加——加了会是一列
> 全是同一个名字的废话。所以 B / C 的表头写了「模型」列，A 的没写。
>
> **连带影响**：第六节缺席时，后面每一节的章节号与图号表号**整体前移一位**，
> 渲染器按实际出现的节现算，骨架这边不用手改——但**对报告时要照实收号**，
> 别拿骨架 C 的「图 11 / 表 5」去对一份没有第六节的报告。

## 八、口径与注意事项

- **值缺失的含义**：TS 为 “—” 表示该等级没有有效配对或无事件，与“评分为 0”不同；
- **BIAS 不是平均误差**：它是频率偏差，>1 表示预报事件偏多，<1 表示偏少；
- **前五节评的是集合平均场**：TS / POD / FAR / 漏报率 / BIAS 都不含成员离散信息，集合的相对优势要看第六节；
- **概率评分与 TS 不可混比**：两者的累积窗口与阈值都不同，AROC 还是逐成员概率口径；
{有对比对象时补这一条（骨架 A 单模型删掉本行）：- **各模型的样本量并不相同**：第一节列的是各份实测配对数，差值来自起报日数而非口径；样本最少的那份名次波动最大，横向比高低前先看那一行；}
- **跨时效不要直接平均后比较模型**：正式对比应使用共同有效样本与固定验证口径；
- 结果来自统一长表（`scores.csv` / `categorical_wide.csv`，概率评分另见 `diagnostics/probability_wide.csv`），逐行可追溯到具体时效与阈值。

## 十、口径与注意事项

- **值缺失的含义**：TS 为 “—” 表示该等级没有有效配对或无事件，与“评分为 0”不同；
- **BIAS 不是平均误差**：它是频率偏差，>1 表示预报事件偏多，<1 表示偏少；
- **前五节评的是集合平均场**：TS / POD / FAR / 漏报率 / BIAS 都不含成员离散信息，集合的相对优势要看第六节；
- **概率评分与 TS 不可混比**：两者的累积窗口与阈值都不同，AROC 还是逐成员概率口径；
{有对比对象时补这一条（骨架 A 单模型删掉本行）：- **各模型的样本量并不相同**：第一节列的是各份实测配对数，差值来自起报日数而非口径；样本最少的那份名次波动最大，横向比高低前先看那一行；}
- **跨时效不要直接平均后比较模型**：正式对比应使用共同有效样本与固定验证口径；
- 结果来自统一长表（`scores.csv` / `categorical_wide.csv`，概率评分另见 `diagnostics/probability_wide.csv`），逐行可追溯到具体时效与阈值。

## 十、口径与注意事项

- **值缺失的含义**：TS 为 “—” 表示该等级没有有效配对或无事件，与“评分为 0”不同；
- **BIAS 不是平均误差**：它是频率偏差，>1 表示预报事件偏多，<1 表示偏少；
- **前五节评的是集合平均场**：TS / POD / FAR / 漏报率 / BIAS 都不含成员离散信息，集合的相对优势要看第六节；
- **概率评分与 TS 不可混比**：两者的累积窗口与阈值都不同，AROC 还是逐成员概率口径；
{有对比对象时补这一条（骨架 A 单模型删掉本行）：- **各模型的样本量并不相同**：第一节列的是各份实测配对数，差值来自起报日数而非口径；样本最少的那份名次波动最大，横向比高低前先看那一行；}
- **跨时效不要直接平均后比较模型**：正式对比应使用共同有效样本与固定验证口径；
- 结果来自统一长表（`scores.csv` / `categorical_wide.csv`，概率评分另见 `diagnostics/probability_wide.csv`），逐行可追溯到具体时效与阈值。
